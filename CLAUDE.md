## What this project is

**I Need A Fix** is a full-stack medical appointment booking app. Patients browse doctors, select available time slots, and book appointments. Doctors view their upcoming bookings and update statuses. Admins manage users and see all bookings.

Stack: FastAPI + SQLModel + PostgreSQL (backend), React + TypeScript + TanStack Router/Query (frontend), Docker Compose (runtime).

## Running the full stack locally

```bash
# Copy .env.example → .env and fill in secrets, then:
docker compose up -d --build
```

- Frontend: http://dashboard.localhost
- Backend API: http://api.localhost
- Adminer (DB browser): http://localhost:8080
- Mailcatcher (email dev UI): http://localhost:1080

Stop with `docker compose down`.

The `prestart` service automatically runs Alembic migrations and seeds initial data before the backend starts.

## Backend commands

The backend uses **uv** (not pip). Run these from inside the backend container or a uv-managed virtualenv.

```bash
# Lint (mypy + ruff check + ruff format check)
cd backend && bash scripts/lint.sh

# Format
cd backend && bash scripts/format.sh

# Tests with coverage
cd backend && bash scripts/test.sh

# Run a single test
cd backend && uv run pytest tests/path/to/test_file.py::test_function_name -v
```

## Frontend commands

```bash
cd frontend

npm run dev        # local dev server (Vite)
npm run build      # TypeScript check + Vite build
npm run lint       # Biome check + auto-fix
```

## Regenerating the frontend API client

The frontend client in `frontend/src/client/` is **auto-generated** from the backend's OpenAPI schema. After changing any backend route or model, regenerate it:

```bash
bash scripts/generate-client.sh
```

This exports the live OpenAPI JSON from FastAPI, writes it to `frontend/openapi.json`, then runs `@hey-api/openapi-ts`. Do not hand-edit files in `frontend/src/client/`.

## Architecture

### Backend layer order

All models in `backend/app/models.py` follow a consistent pattern:

| Class suffix | Purpose |
|---|---|
| `Base` | Shared fields, not a DB table |
| `Create` | Fields required on creation |
| `Update` | Partial update fields (all optional) |
| *(no suffix, `table=True`)* | Actual DB table |
| `Public` | Safe response shape returned to the frontend |

### Request flow

```
frontend → Traefik → FastAPI → deps.py (auth) → route handler → crud.py → DB
```

- **`backend/app/api/deps.py`** — FastAPI dependency injection. `SessionDep` gives a DB session, `CurrentUser` decodes the JWT and returns the logged-in `User`. These are injected into every protected endpoint.
- **`backend/app/api/routes/`** — One file per resource (`appointments`, `doctors`, `items`, `login`, `users`, `utils`, `private`). Route files do permission checks then delegate to `crud.py`.
- **`backend/app/crud.py`** — All DB reads/writes. No business logic lives in route files that isn't a permission check.
- **`backend/app/core/config.py`** — Pydantic Settings; all env vars are validated here.

### Role-based access control

Two fields on `User` control access:

- `is_superuser: bool` — full admin access
- `role: UserRole | None` — either `"doctor"` or `"patient"`, or `None` (unassigned)

Access rules are enforced in route handlers, not middleware. Key invariants:
- Only patients can book appointments, and only for their own email.
- Doctors see only their own appointments.
- Superusers see everything.
- Users with no role assigned get HTTP 403.

### Doctor profile lifecycle

When a superuser assigns the `doctor` role to a user (`PATCH /api/v1/users/{user_id}/role`), `crud.update_user_role` automatically:
1. Creates a `Doctor` profile linked to the user via `Doctor.user_id`.
2. Seeds 30-minute availability slots (09:00–12:00 and 14:00–17:00) for the next 7 days.

When the role is revoked, the `Doctor` profile and all its `DoctorAvailability` rows are deleted. `Appointment` rows linked to a doctor cascade-delete from the DB.

### Booking a slot

`DoctorAvailability.is_booked` is the lock. `crud.create_appointment` checks that the slot exists, belongs to the selected doctor, and is not already booked — then flips `is_booked = True` atomically in the same transaction.

### Frontend routing

TanStack Router with file-based routing. Route files live in `frontend/src/routes/`. The authenticated layout is `_layout.tsx`; all protected pages are under `_layout/`. The generated route tree is at `frontend/src/routeTree.gen.ts` — do not edit it manually (it's regenerated by the Vite plugin on dev start or build).

Frontend API calls use the generated service classes from `frontend/src/client/` (e.g., `AppointmentsService.createAppointment(...)`, `DoctorsService.readDoctors(...)`). Wrap them with TanStack Query (`useQuery` / `useMutation`) for data fetching and cache invalidation.
